# 表示・再生操作の診断（機能変更なし）

対象は公開アプリ実装c186c76。2026-10-16の本人報告を受け、コードと別のloopback検証ページで切り分けた。本人のタブ・作品・キーは操作していない。

## 確認した原因

- `app.js:132` は延長元の`viewed`がfalseの間、キーとプロンプトがあっても生成ボタンを無効にする。`core.js:153`も同じ制限を持つ。
- `app.js:313`の中央プレビューの`ended`イベントだけが`studio.viewed(playingId)`を呼ぶ。単に再生を開始、metadata読込、または外部プレーヤーで視聴しただけでは解除されない。
- `media.js`の実尺・画角計測は別のdetached videoで行われる。完成版として採用済みでも、上記視聴ゲートは残る。
- 履歴の三角印は`span.version-icon`で、イベント処理のない装飾。
- 履歴の「表示」とタイムラインの「再生」は`studio.select(id)`だけを実行し、中央プレビューのsrcと選択表示を切り替える。`video.play()`やscroll処理はない。既に選択中の版なら目に見える変化がない。

## 課金なしの実ブラウザ確認

`/tmp/omni-playback-diagnosis-20261016`の隔離ページ（127.0.0.1:4371）に、ffmpegで作った3秒/6秒のテスト映像とGoogleGatewayのmockを配置。Google originへの接続をCSPで禁止し、実API要求は0件。機能の本体コードはコピー元と同じだが、検証用キーの内部プレースホルダーとmock gatewayのみを差し替えた。本人キーは取得・入力していない。この検証用差し替えは配布物に含めない。

- `loadedmetadata → loadeddata → canplay`後、続きのプロンプトありでも延長ボタンはdisabled。
- `play`後もdisabled。`ended`後はenabled、表示は「再生済み」。
- mockの3→6秒版を採用でき、実際の動画metadataは3.00/6.00秒。
- 履歴「版1を表示」後、見出しとsrcは3秒版へ切り替わるが`paused:true,currentTime:0,duration:3`。
- タイムライン「6秒版を再生」後、6秒版へ切り替わるが`paused:true,currentTime:0,duration:6`。
- 旧版の三角印を押しても選択は6秒版のままで、再生も始まらない。

## 現行の操作と限定修正案

現行版では「表示」で選び、上へスクロールして中央の動画プレーヤーで再生する。延長したい元の版を最後まで再生する必要がある。

これは反応しないように見えるUIと「再生」という表示の不一致であり、マニュアルだけで問題が解消したとは扱わない。限定修正案は、装飾三角印を実際のbuttonにし、表示はプレビューへの移動、再生は選択後の`play()`を行い、失敗時は明示案内すること。自動再生制約への対応が必要。延長の視聴ゲートを任意にする場合は別の仕様判断になる。今回は「機能改修なし」の指示を守り、いずれも実装していない。

本人が実APIの3秒→6秒生成成功を報告した。これは本人の確認結果であり、こちらの実API検証ではない。こちらではGoogle生成・Files送信・課金・実映像の連続性を検証していない。
